# SQL Gen Metadata File Specifications

These files are used by the SQL Generation platform to understand database schemas, domain concepts, and user context. All files can be Excel (.xlsx) or CSV (.csv) unless otherwise noted.

---

## C1. Additional Synonyms (Optional)

**Naming convention:** `<db_name>.<vs_name>_synonyms`
**Upload via:** [Upload Files endpoint](./api-reference.md#b1-upload-files-synonyms-taxonomy-autotaxonomy) (`synonyms_file` parameter)
**Valid extensions:** XLSX, CSV

| Column | Name | Type | Description |
|--------|------|------|-------------|
| 1 | name | string | Alternative/similar name |
| 2 | synonym | string | Another alternative name |
| 3 | preferred_name | string | Full canonical name of the entity |

**Example:**

| name | synonym | preferred_name |
|------|---------|----------------|
| Lake | VCL | Vantage Cloud Lake |
| cloud systems | cloud systems | cloud sites |
| cloud systems | cloud site | cloud sites |

**Notes:**
- `preferred_name` values represent unique concepts
- A concept can have multiple rows to define multiple synonyms
- No full row duplicates allowed

## C2. Taxonomy for Disambiguation (Optional)

**Naming convention:** `<db_name>.<vs_name>_taxonomy_disambiguation`
**Upload via:** [Upload Files endpoint](./api-reference.md#b1-upload-files-synonyms-taxonomy-autotaxonomy) (`taxonomy_disambiguation_file` parameter)
**Valid extensions:** JSON

**Structure:**
```json
{
  "parent_concept": {
    "description": "Description of the parent concept",
    "child_concept_1": {
      "description": "Description of child",
      "database.table_name": ["column_name"]
    },
    "child_concept_2": {
      "description": "Description of child",
      "database.table_name": ["column_name"]
    }
  }
}
```

**Example:**
```json
{
  "score": {
    "description": "Customer satisfaction and early warning metrics",
    "ews score": {
      "description": "Early Warning Score metrics from the EWS view",
      "customer360.customer360_ews_vw": ["ews_score"]
    },
    "nps score": {
      "description": "Net Promoter Score metrics from the NPS view",
      "customer360.customer360_nps_vw": ["nps_score"]
    }
  }
}
```

**Purpose:** When a user asks about an ambiguous concept (e.g., "scores"), the agent identifies the parent concept, sees it has multiple children, and asks a follow-up question to disambiguate.

## C3. Index Scripts (Required — Auto-generated)

These are **not user-created files**. They are generated automatically when the [Run Index Scripts endpoint](./api-reference.md#b2-run-index-scripts) is called:

- **FeatureIndex** — indexes table/column features for prompt matching
- **FeatureIndexDescription** — indexes feature descriptions
- **IndexColumnUniqueness** — indexes column uniqueness statistics

All three run simultaneously and are mandatory.

## C4. Taxonomy for Logical Expression and Tense (Optional — Auto-generated)

**Naming convention:** `<db_name>.<vs_name>_taxonomy`
**Generated by:** [AutoTaxonomy endpoint](./api-reference.md#b31-run-autotaxonomy)
**Valid extensions:** JSON

**Structure:**
```json
{
  "concept": {
    "past_tense": {
      "AND|OR": ["table.column operator value", ...]
    },
    "future_tense": {
      "AND|OR": ["table.column operator value", ...]
    }
  }
}
```

**Example:**
```json
{
  "out of support": {
    "past_tense": {
      "AND": [
        "customer360.customer360_site_vw.eos_hw < CURRENT_DATE",
        "customer360.customer360_site_vw.eos_sw < CURRENT_DATE"
      ]
    },
    "future_tense": {
      "OR": [
        "customer360.customer360_site_vw.eos_hw >= CURRENT_DATE",
        "customer360.customer360_site_vw.eos_sw >= CURRENT_DATE"
      ]
    }
  }
}
```

**Workflow:**
1. Run AutoTaxonomy → generates initial file based on column descriptions
2. Download the file
3. Human curates/validates the generated taxonomy
4. Upload the curated file back via the Upload Files endpoint

**Important:** Column descriptions must be clear and descriptive for AutoTaxonomy to generate accurate mappings.

## C5. Table Descriptions (Required)

**Naming convention:** `<db_name>.<vs_name>_table_description`
**Upload via:** [Upload Table Descriptions endpoint](./api-reference.md#b61-upload-table-descriptions)
**Valid extensions:** XLSX, CSV

| Column | Name | Type | Description |
|--------|------|------|-------------|
| 1 | database_name | string | Database containing the table |
| 2 | table_name | string | Table name |
| 3 | table_comment | string | Descriptive comment for the table |

**Example:**

| database_name | table_name | table_comment |
|---------------|------------|---------------|
| customer360 | customer360_site | Stores instances of account site characteristics that change over time |

**Notes:**
- When uploading with `replace_existing=true`, the API removes all existing comments first then adds from file
- Include ALL existing comments you want to keep in the file, plus any new ones

---

## C6. Column Descriptions (Required)

**Naming convention:** `<db_name>.<vs_name>_column_description`
**Upload via:** [Upload Column Descriptions endpoint](./api-reference.md#b71-upload-column-descriptions)
**Valid extensions:** XLSX, CSV

| Column | Name | Type | Description |
|--------|------|------|-------------|
| 1 | database_name | string | Database containing the table |
| 2 | table_name | string | Table containing the column |
| 3 | column_name | string | Column name |
| 4 | column_comment | string | Descriptive comment for the column |

**Example:**

| database_name | table_name | column_name | column_comment |
|---------------|------------|-------------|----------------|
| customer360 | customer360_site | sales_account_number | The number identifying the account for sales motions |

**Notes:**
- Same `replace_existing` behavior as table descriptions
- Clear column descriptions improve AutoTaxonomy accuracy

## C8. User Profiles (Optional)

**Naming convention:** `<db_name>.<vs_name>_user_profiles`
**Upload via:** [Upload User Profiles endpoint](./api-reference.md#b51-upload-user-profiles)
**Valid extensions:** XLSX, CSV

| Column | Name | Type | Description |
|--------|------|------|-------------|
| 1 | USERNAME | string | Database username (must be unique) |
| 2 | ACCT_TEAM_MEMBER_QLID | string | Employee/team member QLID |
| 3 | ACCT_TEAM_MEMBER_ROLE_NAME | string | Role name/title |
| 4 | ACCT_TEAM_MEMBER_NAME | string | Full name (Last, First) |

**Example:**

| USERNAME | ACCT_TEAM_MEMBER_QLID | ACCT_TEAM_MEMBER_ROLE_NAME | ACCT_TEAM_MEMBER_NAME |
|----------|----------------------|---------------------------|----------------------|
| juan_05 | JM090039 | CUSTOMER SUCCESS MANAGER | Mendez, Juan |
| alessia_01 | AC090003 | CONTRACT MANAGER | Corbin, Alessia |

**Purpose:** Enables the agent to resolve "my" / "I" in user queries to a specific identity for WHERE clause construction.

**Admin setup required for each user:**
```sql
-- Create user
CREATE USER <username> AS PERM = 10000 PASSWORD = <password>;

-- Grant access
GRANT SELECT ON <database> TO <username>;
GRANT SELECT ON TD_SYSAI TO <username>;
GRANT TD_AIUser_<database> TO <username>;

-- Insert profile row
INSERT INTO <database>.user_profile
VALUES ('<username>', 'Employee_ID', 'Title', 'Last, First');
```
