# Column Attributes and Constraints — Complete Reference

> Source: Teradata SQL Data Definition Language Syntax and Examples, B035-1144, Release 20.00, Chapter 3

## Column Data Type Attributes

### UPPERCASE

Forces character data to uppercase on storage.

```sql
column_name VARCHAR(50) UPPERCASE
```

- Applied on INSERT and UPDATE
- Comparisons use the uppercased value
- Cannot be used with CASESPECIFIC

### CASESPECIFIC / NOT CASESPECIFIC

Controls case sensitivity for comparisons.

```sql
column_name VARCHAR(50) CASESPECIFIC       -- comparisons are case-sensitive
column_name VARCHAR(50) NOT CASESPECIFIC   -- comparisons ignore case (Teradata mode default)
```

### FORMAT

Specifies display format for the column.

```sql
column_name DATE FORMAT 'YYYY-MM-DD'
column_name DECIMAL(10,2) FORMAT 'ZZZ,ZZ9.99'
column_name INTEGER FORMAT 'Z(9)9'
```

### TITLE

Assigns a column heading for display.

```sql
column_name INTEGER TITLE 'Employee Number'
```

### NAMED

Assigns an alias to a column in a view or derived table.

```sql
column_name NAMED alias_name
```

### DEFAULT and WITH DEFAULT

```sql
-- Explicit default value
column_name INTEGER DEFAULT 0
column_name VARCHAR(20) DEFAULT 'UNKNOWN'
column_name DATE DEFAULT DATE
column_name TIMESTAMP DEFAULT CURRENT_TIMESTAMP

-- System-generated default (zero for numbers, spaces for strings, current date for dates)
column_name INTEGER WITH DEFAULT
```

### CHARACTER SET

```sql
column_name VARCHAR(100) CHARACTER SET UNICODE
column_name CHAR(50) CHARACTER SET LATIN
column_name VARCHAR(200) CHARACTER SET KANJISJIS
column_name CHAR(100) CHARACTER SET GRAPHIC
```

### NULL / NOT NULL

```sql
column_name INTEGER NOT NULL          -- rejects NULL values
column_name VARCHAR(50) NULL          -- allows NULL (default in ANSI mode)
column_name INTEGER NOT NULL DEFAULT 0  -- NOT NULL with a default
```

- In Teradata mode, columns default to NOT NULL
- In ANSI mode, columns default to NULL

## Compression Attributes

### Value-List Compression

Compresses columns that contain frequently repeated values by storing them in the table header.

```sql
-- Single value
column_name CHAR(1) COMPRESS ('Y')

-- Multiple values (up to 255)
column_name VARCHAR(20) COMPRESS ('OPEN', 'CLOSED', 'PENDING', 'CANCELLED')

-- NULL compression
column_name INTEGER COMPRESS

-- NULL plus values
column_name SMALLINT COMPRESS (0, 1, 2, 3, NULL)
```

#### Rules
- Maximum 255 distinct compress values per column
- Values must match the column data type exactly
- Compressed values are stored in the table header (not in each row)
- Savings are proportional to the frequency of compressed values
- Cannot use value-list compression on PI columns

### Multi-Value Compression (MVC) Size Limits

| Data Type | Max Values |
|-----------|------------|
| BYTEINT | 255 |
| SMALLINT | 255 |
| INTEGER | 255 |
| BIGINT | 255 |
| CHAR(n) | 255 |
| VARCHAR(n) | 255 |
| DATE | 255 |
| DECIMAL | 255 |

### Algorithmic Compression (ALC)

For large data values (VARCHAR, CLOB, BLOB).

```sql
-- LZ compression
column_name VARCHAR(64000) COMPRESS USING TD_LZ_COMPRESS DECOMPRESS USING TD_LZ_DECOMPRESS

-- UNICODE compression for character data
column_name VARCHAR(32000) CHARACTER SET UNICODE
    COMPRESS USING TD_SYSFNLIB.TD_UNICODE_COMPRESS
    DECOMPRESS USING TD_SYSFNLIB.TD_UNICODE_DECOMPRESS
```

#### Built-in ALC Functions

| Compress Function | Decompress Function | Best For |
|-------------------|---------------------|----------|
| `TD_LZ_COMPRESS` | `TD_LZ_DECOMPRESS` | General-purpose large strings |
| `TD_UNICODE_COMPRESS` | `TD_UNICODE_DECOMPRESS` | Unicode character data |

### AUTO COMPRESS

Enables automatic column-level compression for column-partitioned tables.

```sql
CREATE TABLE t1 (...) AUTO COMPRESS;
```

## Identity Columns

Identity columns generate unique sequential values automatically.

```sql
-- Always generated (cannot be overridden by INSERT)
column_name INTEGER GENERATED ALWAYS AS IDENTITY
    (START WITH 1 INCREMENT BY 1 MINVALUE 1 MAXVALUE 2147483647 NO CYCLE)

-- Generated by default (INSERT can override)
column_name BIGINT GENERATED BY DEFAULT AS IDENTITY
    (START WITH 1000 INCREMENT BY 1)
```

### Identity Attributes

| Attribute | Description | Default |
|-----------|-------------|---------|
| `START WITH n` | Initial value | 1 |
| `INCREMENT BY n` | Step between values | 1 |
| `MINVALUE n` | Minimum value | 1 (or -2^63 for negative increment) |
| `MAXVALUE n` | Maximum value | Data type maximum |
| `NO CYCLE` | Error when max is reached | Default |
| `CYCLE` | Restart from MINVALUE when max is reached | — |

### Rules
- Only one identity column per table
- Must be a numeric type (INTEGER, SMALLINT, BIGINT, DECIMAL with scale 0)
- Cannot be used with DEFAULT or WITH DEFAULT
- GENERATED ALWAYS: INSERT must omit the column or use DEFAULT
- GENERATED BY DEFAULT: INSERT can supply an explicit value

## Column Constraints

### PRIMARY KEY (Column-Level)

```sql
column_name INTEGER NOT NULL PRIMARY KEY
```

- Implies NOT NULL and UNIQUE
- Creates a UPI if no explicit PRIMARY INDEX is defined
- One PRIMARY KEY per table

### UNIQUE (Column-Level)

```sql
column_name VARCHAR(50) UNIQUE
```

- Creates a USI (Unique Secondary Index)
- Allows NULL unless NOT NULL is also specified

### CHECK (Column-Level)

```sql
column_name INTEGER CHECK (column_name BETWEEN 1 AND 100)
column_name CHAR(1) CHECK (column_name IN ('Y', 'N'))
column_name DECIMAL(10,2) CHECK (column_name >= 0)
```

### REFERENCES (Column-Level Foreign Key)

```sql
column_name INTEGER REFERENCES parent_table(parent_column)
```

## Table Constraints

### PRIMARY KEY (Table-Level)

```sql
CONSTRAINT pk_name PRIMARY KEY (col1, col2)
```

### UNIQUE (Table-Level)

```sql
CONSTRAINT uq_name UNIQUE (col1, col2)
```

### CHECK (Table-Level)

```sql
CONSTRAINT chk_dates CHECK (end_date >= start_date)
CONSTRAINT chk_range CHECK (min_val < max_val)
```

### FOREIGN KEY (Table-Level)

```sql
CONSTRAINT fk_name FOREIGN KEY (local_col)
    REFERENCES parent_table(parent_col)
    [WITH NO CHECK OPTION]
```

- `WITH NO CHECK OPTION` skips referential integrity check for existing rows during table creation
- Foreign keys create referential integrity constraints but do NOT prevent INSERT/UPDATE in Teradata — they are informational for the optimizer

## Derived Period Columns

Period columns represent a range of time (temporal support).

```sql
CREATE TABLE t1 (
    emp_id      INTEGER NOT NULL,
    emp_name    VARCHAR(100),
    start_date  DATE NOT NULL,
    end_date    DATE NOT NULL,
    PERIOD FOR emp_period (start_date, end_date)
)
PRIMARY INDEX (emp_id);
```

### Rules
- The two boundary columns must be the same temporal data type (DATE, TIMESTAMP)
- The derived period column (`emp_period`) is virtual — not stored
- Used with temporal qualifiers: `CURRENT VALIDTIME`, `AS OF`, `BETWEEN...AND`

## Row-Level Security Constraint Columns

```sql
CREATE TABLE t1 (
    ...
    security_col CONSTRAINT security_constraint_name
)
PRIMARY INDEX (...);
```

- Requires `CONSTRAINT ASSIGNMENT` privilege
- The constraint must be previously created with `CREATE CONSTRAINT`
